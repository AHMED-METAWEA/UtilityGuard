How a reading becomes a fix

The pipeline in the order the code runs it

EVERY 2 SECONDS

1. Simulator89 sensor readings, with injected faults
2. Expected valuesA twin with the same seed and no faults; forecast and early warning
3. DetectorA fault must last 3 readings; one root cause is one incident
4. Screen and TelegramPushed live to the map; alerts sent to the chat

FOR EACH INCIDENT

5. PriceEGP per hour of delay, P10 to P90
6. Agents explainWater, power and cooling specialists; numbers checked
7. Board plan720 crew orders tried; the cheapest proposed
8. A person decidesApprove, change the order (priced first) or reject

AFTER APPROVAL

9. Crews workOn the demo clock; the repair ends the fault
10. Detector confirmsThe detector, not the crew, says it is gone
11. Audit logEvery step, hash-chained: an edit breaks the chain
Closed loop: the cleared fault returns to live readings, and edited assumptions recompute every price
