# Decisions Log

| # | Decision | Reason |
| --- | --- | --- |
| D1 | Repo is `AHMED-METAWEA/UtilityGuard` (not `UtilityGuard-Twin` as in the kickoff). Work on `dev`. | The owner created this repo. |
| D2 | No `freebuff/` folder exists, so everything is built from scratch. | The repo only has a README and .gitignore. |
| D3 | The concept image [reference/concept-view.png](reference/concept-view.png) is a mood and layout reference, not a pixel spec. We model the capital's real layout: the Government, Presidential and Diplomatic districts in the north, the Green River running east-west, the CBD below it, residential districts R2 to R8 and Medical City. Zone polygons sit on the real coordinates (about 30.02 N, 31.75 E) over a dark OSM basemap (CARTO Dark Matter, no key needed). The overall feel is taken from the image (dark glass panels, glowing network lines, a finding card with numbered reasons and the formula, act now / delay / saving tiles, chat with routing chips), but the detailed design is our own. | The owner confirmed the image only shows the feel of a slice of the capital. |
| D4 | Python deps are managed with `venv` + `pip` (`requirements.txt`). | `uv` is not installed and pip is enough. |
| D5 | Forecasting uses LightGBM on lag, hour, weekday and temperature features, trained on 60 days of simulated history. Failure prediction uses a gradient-boosting classifier on health features. Anomaly detection combines rolling z-score rules with Isolation Forest. | Trains in seconds, gives feature importances, and is reliable. Prophet and LSTM add risk for little gain. |
| D6 | Groq models: `llama-3.3-70b-versatile` for the orchestrator and `llama-3.1-8b-instant` for the specialists. Both are configurable in `.env`. | Matches spec 8.4 (strong orchestrator, fast specialists). |
| D7 | Agents produce text only. The finding numbers are filled in by code from the cost engine, and a number checker removes or flags any figure in the LLM text that does not match the calculation record. | Spec 9A. |
| D8 | Storage is in memory, with JSON files for assumptions and the fallback cache. | Demo scope. |
| D9 | PDF reports are made with ReportLab on the server. | Pure Python, nothing to install on the system. |
| D10 | The frontend is in TypeScript. TS types are generated by hand from the Pydantic schemas, and the fixture JSON files are the shared truth checked by tests on both sides. | Keeps the two sides in sync without a codegen step. |
