# Decisions Log

| # | Decision | Reason |
| --- | --- | --- |
| D1 | Repo is `AHMED-METAWEA/UtilityGuard` (not `UtilityGuard-Twin` as in the kickoff). Work on `dev`. | The owner created this repo. |
| D2 | No `freebuff/` folder exists, so everything is built from scratch. | The repo only has a README and .gitignore. |
| D3 | The concept image [reference/concept-view.png](reference/concept-view.png) is a mood and layout reference, not a pixel spec. We model the capital's real layout: the Government, Presidential and Diplomatic districts in the north, the Green River running east-west, the CBD below it, residential districts R2 to R8 and Medical City. Zone polygons sit on the real coordinates (about 30.02 N, 31.75 E) over a dark OSM basemap (CARTO Dark Matter, no key needed). The overall feel is taken from the image (dark glass panels, glowing network lines, a finding card with numbered reasons and the formula, act now / delay / saving tiles, chat with routing chips), but the detailed design is our own. | The owner confirmed the image only shows the feel of a slice of the capital. |
| D4 | Python deps are managed with `venv` + `pip` (`requirements.txt`). | `uv` is not installed and pip is enough. |
| D5 | Forecasting uses LightGBM on lag, hour, weekday and temperature features, trained on 60 days of simulated history. Failure prediction uses a gradient-boosting classifier on health features. Anomaly detection combines rolling z-score rules with Isolation Forest. | Trains in seconds, gives feature importances, and is reliable. Prophet and LSTM add risk for little gain. |
| D6 | Groq models: `openai/gpt-oss-120b` for the orchestrator and `openai/gpt-oss-20b` for the specialists (the Llama models are not available on this key). Both are configurable in `.env`. | Matches spec 8.4 (strong orchestrator, fast specialists). |
| D7 | Agents produce text only. The finding numbers are filled in by code from the cost engine, and a number checker removes or flags any figure in the LLM text that does not match the calculation record. | Spec 9A. |
| D8 | Storage is in memory, with JSON files for assumptions and the fallback cache. | Demo scope. |
| D9 | PDF reports are made with ReportLab on the server. | Pure Python, nothing to install on the system. |
| D10 | The frontend is in TypeScript. TS types are generated by hand from the Pydantic schemas, and the fixture JSON files are the shared truth checked by tests on both sides. | Keeps the two sides in sync without a codegen step. |
| D11 | Shape clarifications (camelCase, reading batch, finding `explain` block, incident, snapshot) are recorded in contract 4.9. | Contract-first rule. |
| D12 | The twin now sits on the real NAC geography from OpenStreetMap: CBD and the Iconic Tower in the west, Arts and Culture City, the Government District (Parliament, Cabinet, ministries) in the east, Justice City, the Presidential District, R2, and residential districts north and north-east. R2 is the only official R number used; the others have descriptive names so we do not show wrong labels. Real buildings, roads, parks, water and the Green River are in frontend/public/geo (ODbL, see ATTRIBUTION.txt) and work offline. | Owner wants it to look like the real capital; ACUD reviewers will know the layout. |
| D13 | Claude Code designs and builds the new frontend itself (owner request). Playwright MCP and Context7 MCP are installed for visual checks and current library docs. | Owner request. |
| D14 | Public price references are attached to each assumption (`app/cost/references.py`) and shown with an evidence verdict (consistent, partly, differs, related, none). The defaults are **not** changed to match them; the owner edits prices in the app. | The owner chose to keep the planning defaults and edit in the app. Honest labels matter more than matching a source. |
| D15 | The board's decision is computed by code (exhaustive search over crew orders, cost model, 300 price scenarios). A language model may only re-voice sentences the code composed, and its text is rejected if a figure or asset differs. | Spec 9A: numbers come from code. A model that argues its own numbers cannot be audited. |
| D16 | The board only proposes. Crews move only after a person approves; the person may approve a different order, which the server prices first, or reject with a reason. | A government utility needs a human decision-maker on record. |
| D17 | Approved plans run on a demo clock (`DISPATCH_SECONDS_PER_HOUR`, default 20 s per planned hour). Plan hours and costs are not scaled. The detector, not the crew, confirms a problem is clear. | A real three hour repair cannot be watched, and the closing check must be independent of the actor. |
| D18 | A problem is identified by (fault kind, asset), not by alert id. | Live test: the detector re-raised a burst as a slow leak mid-plan under a new alert id, and the plan wrongly skipped the crew. |
| D19 | The decision log is an append-only JSON-lines file with a SHA-256 hash chain, kept across simulation resets and restarts. Operator identity is whatever is typed. | Tamper evidence without a database. Real authentication is future work and is stated as a limit. |
| D20 | Five demand-forecast models are compared on the same split (LightGBM, Ridge, Random Forest, seasonal smoothing, an ensemble). The live forecast stays LightGBM although the ensemble has the lowest out-of-fold error. | The owner decided to keep LightGBM. The comparison page states the difference openly. |
