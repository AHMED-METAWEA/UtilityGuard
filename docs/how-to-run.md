# إزاي تشغّل Care Grid، خطوة بخطوة

الملف ده بيشرح تشغيل المشروع من الصفر لحد ما تفتحه في المتصفح، وإزاي توقفه، وتعمل إيه لو حاجة وقفت معاك.
كل الأوامر بتتكتب في الـ Terminal (على الماك: افتح **Terminal** أو الـ Terminal اللي جوه VS Code).

---

## لو مستعجل: التلات أوامر دول وبس

لو الجهاز اتجهّز قبل كده (وده حال جهازك دلوقتي):

```bash
cd ~/Desktop/UtilityGuard
./run_all.sh
```

استنى لحد ما تظهر الرسالة دي:

```
  The twin               http://localhost:8000
  Healthcare dashboard   http://localhost:8501   (also inside the twin: Healthcare tab)
  Press Ctrl+C to stop both.
```

وبعدها افتح **http://localhost:8000** في المتصفح.
وعشان توقف كل حاجة: ارجع للـ Terminal نفسه ودوس **Ctrl+C**.

باقي الملف بيشرح كل خطوة من دول بالتفصيل، ويقولك تعمل إيه لو حاجة منهم ما اشتغلتش.

---

## 1. المشروع بيتكون من إيه وهو شغال

لما تشغّل `run_all.sh` بيقوم برنامجين مع بعض:

| البرنامج | العنوان | هو إيه |
|---|---|---|
| **التوأم الرقمي (Care Grid)** | http://localhost:8000 | مشروعك: الخريطة، الشبكات التلاتة، الأعطال، الوكلاء، مجلس الوكلاء، سجل القرارات. السيرفر (FastAPI) هو اللي بيعرض الواجهة كمان، فمش محتاج تشغّل الواجهة لوحدها. |
| **داشبورد جيهان (الرعاية الصحية)** | http://localhost:8501 | مشروع جيهان زي ما هو (Streamlit). بيظهر كمان جوه التوأم في تبويب **Healthcare**. |

مفيش قاعدة بيانات ولا GPU. كل حاجة بتشتغل على اللابتوب.

## 2. أول مرة على جهاز جديد (التجهيز)

**الخطوات دي بتتعمل مرة واحدة بس.** جهازك متجهّز خلاص، فاقرا الجزء ده لو هتشغّل المشروع على جهاز تاني (لابتوب العرض مثلاً).

### 2.1 البرامج المطلوبة على الجهاز

| البرنامج | الإصدار | تتأكد منه إزاي |
|---|---|---|
| Python | 3.12 | `python3 --version` |
| Node.js | 20 أو أحدث | `node --version` |
| git | أي إصدار | `git --version` |

على جهازك دلوقتي: Python 3.12.4 و Node 22.15.1.

> **انتبه:** لو `python3 --version` طلّع إصدار تاني (زي اللي بيجي مع Anaconda)، ما تستعملهوش لتشغيل المشروع. المشروع ليه بيئة Python خاصة بيه (`.venv`) فيها كل المكتبات. Python بتاع Anaconda ناقصه مكتبات (زي `langgraph`)، وهيطلعلك أخطاء.

### 2.2 تنزّل المشروع

```bash
cd ~/Desktop
git clone https://github.com/AHMED-METAWEA/UtilityGuard.git
cd UtilityGuard
git checkout dev          # الشغل كله على dev (main فيه أول commit بس)
```

### 2.3 تجهّز الـ backend (السيرفر)

```bash
cd backend
python3 -m venv .venv                          # بيعمل بيئة Python خاصة بالمشروع
.venv/bin/pip install -r requirements.txt      # بيسطّب المكتبات (كام دقيقة)
cp .env.example .env                           # ملف الإعدادات والمفاتيح
```

بعد كده افتح `backend/.env` وحط مفتاح Groq:

```
GROQ_API_KEY=gsk_...........
```

- المفتاح بتجيبه من console.groq.com (الخطة المجانية كفاية).
- **من غير مفتاح المشروع برضه بيشتغل:** الوكلاء بيردّوا من إجابات متسجّلة قبل كده، والحسابات والكشف والمجلس شغالين عادي لأن الكود هو اللي بيحسبهم مش الموديل.
- **الملف `.env` عمره ما يترفع على GitHub.** هو متسجّل في `.gitignore`، فما تشيلوش من هناك.

### 2.4 تجهّز الواجهة (frontend)

```bash
cd ../frontend
npm install           # بيسطّب مكتبات الواجهة
npm run build         # بيبني الواجهة في frontend/dist، والسيرفر بيعرضها من هناك
```

> لو نسيت الخطوة دي، `run_all.sh` هيعملها لوحده أول مرة.

### 2.5 مشروع جيهان

مش محتاج تعمل حاجة. أول مرة تشغّل `run_all.sh` بيعمل الآتي لوحده:
1. ينزّل مشروع جيهان من GitHub في `integration/health/their-app` (الفولدر ده مش جوه الريبو بتاعك، ومحدش بيعدّل فيه).
2. يعمله بيئة Python خاصة بيه ويسطّب مكتباته (أول مرة بس، كام دقيقة).

عشان كده **أول تشغيل على جهاز جديد محتاج إنترنت.**

## 3. التشغيل كل مرة

```bash
cd ~/Desktop/UtilityGuard
./run_all.sh
```

### هتشوف إيه في الـ Terminal

1. سطر بالعناوين (اللي فوق) و `Press Ctrl+C to stop both.`
2. سطور من السيرفر ومن Streamlit. ده طبيعي.

### أول تشغيل في اليوم ممكن ياخد حوالي 3 دقايق

موديلات التنبؤ (LightGBM ونموذج الأعطال) بتتدرّب وتتحفظ في `backend/data/models.pkl`. لو الملف ده قديم (اتدرّب قبل النهارده) أو مش موجود، السيرفر بيعيد التدريب وهو بيقوم، **وده بياخد حوالي 3 دقايق** وأقل من 700 MB رامات. التشغيلات اللي بعدها في نفس اليوم بتقوم في ثواني.

> **نصيحة للعرض:** شغّل المشروع قبل العرض بـ 10 دقايق على الأقل، عشان التدريب يكون خلص ويفضل السيرفر شغال.

### تعرف إن السيرفر جاهز إزاي

افتح Terminal تاني واكتب:

```bash
curl http://localhost:8000/api/v1/health
```

لو رجعلك حاجة زي `{"status":"ok","llm":"live",...}` يبقى جاهز. ولو قالك `Connection refused` استنى شوية وجرّب تاني (غالباً لسه بيدرّب).

بعدها افتح **http://localhost:8000**.

### أول حاجة تبص عليها في الشريط اللي فوق

| اللي مكتوب | معناه |
|---|---|
| `Agents: live` | الوكلاء بيكلّموا موديل Groq الحقيقي. |
| `Agents: recorded` | الوكلاء بيردّوا من إجابات متسجّلة: يا إما مفيش مفتاح، يا إما مفيش نت، يا إما رصيد اليوم المجاني خلص (200 ألف token في اليوم). **الأرقام مش بتتأثر**، الكلام الشارح بس هو اللي بيتغيّر. |
| `EN \| عربي` | اللغة اللي الوكلاء بيتكلموا بيها (الشرح، الشات، المجلس، رسايل Telegram). |

## 4. الإيقاف

ارجع للـ Terminal اللي شغّلت فيه `run_all.sh` ودوس **Ctrl+C**. ده بيقفل البرنامجين مع بعض.

### لو قفلت الـ Terminal من غير Ctrl+C، أو البورت فضل محجوز

هتعرف إن ده حصل لما تشغّل تاني ويطلعلك `address already in use`. الحل:

```bash
lsof -nP -iTCP:8000 -iTCP:8501 -sTCP:LISTEN      # بيوريك مين ماسك البورتين
pkill -f "uvicorn app.main:app"                  # يقفل سيرفر التوأم
pkill -f "streamlit run"                         # يقفل داشبورد جيهان
```

وبعدها شغّل `lsof` تاني: لو ما طلّعش حاجة يبقى البورتين فاضيين وتقدر تشغّل من جديد.

## 5. طرق تانية للتشغيل

### تشغّل التوأم لوحده من غير مشروع جيهان

```bash
cd ~/Desktop/UtilityGuard/backend
PYTHONPATH=. .venv/bin/uvicorn app.main:app --port 8000
```

تبويب Healthcare هيكتبلك "The healthcare dashboard is not running"، وباقي المشروع كله شغال عادي.

### تشغّل من غير إنترنت أو من غير ما تصرف من رصيد Groq

```bash
LLM_OFFLINE=1 ./run_all.sh
```

الوكلاء هيردّوا من الإجابات المتسجّلة (`backend/data/fallback_cache.json`). الكشف والتكاليف والمجلس والموافقة وسجل القرارات مش محتاجين الموديل أصلاً.

> **لو العرض في مكان النت فيه ضعيف:** جرّب سيناريو العرض كله مرة وإنت متصل، عشان الإجابات تتسجّل، وبعدها شغّل بـ `LLM_OFFLINE=1` في العرض نفسه.

### توقف رسايل Telegram مؤقتاً

```bash
ALERTS_ENABLED=0 ./run_all.sh
```

أي إعداد تكتبه قبل `./run_all.sh` بيكسب الإعداد اللي في `.env`.

### لو عدّلت حاجة في الواجهة

`run_all.sh` بيبني الواجهة **لو `frontend/dist` مش موجود بس**. يعني لو عدّلت حاجة في `frontend/src` لازم تبني تاني بنفسك، وإلا هتفضل تشوف النسخة القديمة:

```bash
cd ~/Desktop/UtilityGuard/frontend
npm run build
```

وبعدها اعمل Refresh للصفحة.

أثناء التطوير ممكن تستعمل `npm run dev` (على http://localhost:5173)، وده بيحدّث الصفحة لوحده مع كل تعديل. لازم السيرفر يكون شغال على 8000 جنبه.

## 6. Telegram (اختياري)

المشروع بيبعت على Telegram حاجتين: **تنبيه لكل مشكلة** (لما تفتح أو تكبر أو تتحل، والإنذارات المبكرة) و**ملخص الصبح** كل يوم الساعة 7.

عشان تشغّله:
1. في Telegram كلّم **@BotFather** واعمل bot جديد (`/newbot`)، وهيدّيك token.
2. ابعت أي رسالة للـ bot بتاعك.
3. حط الاتنين في `backend/.env`:
   ```
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_CHAT_ID=...
   ```
4. اعمل restart للمشروع (Ctrl+C وبعدين `./run_all.sh`).

> **مهم:** بعد العرض الغي الـ token. كلّم @BotFather واكتب `/revoke`، واختار الـ bot. أي حد معاه الـ token يقدر يبعت باسم الـ bot.

## 7. سيناريو العرض في دقيقتين

ده المسار اللي بيوري أهم حاجة في المشروع: مجلس الوكلاء بيقترح ترتيب الإصلاح، والبني آدم هو اللي بيوافق.

1. من الشريط اللي فوق افتح **Scenario lab**، وشغّل **Three failures at once** (ماسورة تنفجر، chiller يقع، ومحطة كهرباء تفصل في نفس الدقيقة، والطواقم أقل من المشاكل).
2. روح على **Incidents**.
3. استنى المجلس يتجمّع لوحده (حوالي 30 ثانية بعد ما الأعطال تستقر)، واقرا المحضر والجدول الزمني بتاع الطواقم.
4. اكتب اسمك في خانة **Operator name**، ودوس **Change the order**، وحرّك شغلانة، وهتشوف التكلفة الزيادة بالظبط قبل ما توافق.
5. دوس **Approve plan**. الطواقم بتبدأ على ساعة العرض (ساعة الشغل المخططة = 20 ثانية)، والأعطال بتختفي من التوأم، والكاشف هو اللي بيأكد إنها اتحلّت.
6. افتح **Decision log** ودوس **Verify now**: بيتأكد إن السجل ما اتلعبش فيه.

لو عايز تبدأ من الأول: من **Scenario lab** دوس **Reset twin** وأكّد. ده بيوقف كل السيناريوهات ويمسح المشاكل.

## 9. مشاكل شائعة وحلها

| اللي بيحصل | السبب | الحل |
|---|---|---|
| `permission denied: ./run_all.sh` | الملف مش متعلّم إنه بيتشغّل | `chmod +x run_all.sh` |
| `address already in use` | نسخة قديمة لسه شغالة | الجزء 4 (`pkill`) |
| `ModuleNotFoundError: No module named 'langgraph'` (أو أي مكتبة) | استعملت Python غلط (Anaconda مثلاً) | استعمل `.venv/bin/python` أو `.venv/bin/uvicorn` جوه `backend` |
| `ModuleNotFoundError: No module named 'app'` | ناقصك `PYTHONPATH=.` أو مش واقف في `backend` | `cd backend` وحط `PYTHONPATH=.` قبل الأمر |
| `curl` بيقول `Connection refused` أول ما تشغّل | السيرفر لسه بيدرّب الموديلات | استنى حوالي 3 دقايق |
| الصفحة فاضية أو `Not Found` على 8000 | الواجهة مش متبنية | `cd frontend && npm run build` |
| عدّلت في الواجهة والتعديل مش باين | `dist` قديم | `npm run build` واعمل Refresh |
| `Agents: recorded` مع إن المفتاح موجود | النت قاطع، أو رصيد Groq بتاع اليوم خلص (الخطأ 429) | استنى لبكرة، أو كمّل بالإجابات المتسجّلة (الأرقام زي ما هي) |
| تبويب Healthcare فاضي | داشبورد جيهان لسه بيقوم أو مش شغال | افتح http://localhost:8501 لوحده. لو مش شغال، شوف رسايل الخطأ في الـ Terminal |
| أول تشغيل على جهاز جديد بيقف عند `Cloning the healthcare project` | مفيش نت أو GitHub مش بيرد | اتأكد من النت وشغّل تاني |
| رسايل Telegram كتير وإنت بتجرّب | التنبيهات شغالة | `ALERTS_ENABLED=0 ./run_all.sh` |
